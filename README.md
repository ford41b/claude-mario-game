# Super Mario Bros. for the browser

A recreation of the NES game *Super Mario Bros.* (1985) that runs in a web
browser. The game program is a hand port of the original's code to JavaScript,
done routine by routine from the community disassembly. That covers the
physics, collision, enemy behavior, scrolling, level data, scoring, timers and
sound effects. The game logic matches the original's subpixel arithmetic and
its quirks.

All 8 worlds and 32 levels are in, including bonus rooms, warp zones, coin
heaven, the castle mazes, the ending and the second quest (hard mode with
world select).

## Running it

You need [Node.js](https://nodejs.org/) 18 or newer. There are no
dependencies to install.

```sh
npm start
```

Then open <http://localhost:8080/>. To use a different port, run
`node tools/serve.mjs 3000`.

You can also open `index.html` straight from disk. It works, but some
browsers then fall back to an older audio path.

Click the page or press any key once so the browser allows sound.

## Controls

| NES button | Keyboard | Gamepad (standard mapping) |
| --- | --- | --- |
| D-pad | Arrow keys or `W` `A` `S` `D` | D-pad or left stick |
| A (jump, swim) | `X`, `K` or `Space` | Bottom or right face button |
| B (run, fireball) | `Z` or `J` | Left or top face button |
| Start (pause) | `Enter` | Start |
| Select | `Right Shift` or `Tab` | Back / Select |

| Other keys | |
| --- | --- |
| `P` | Freeze or resume emulation (separate from the game's own pause) |
| `F2` | Reset to the title screen, like the console's reset button (the top score is kept) |
| `M` | Mute |
| `F` | Fullscreen |

The buttons under the screen do the same things. They also set the volume and
switch between square pixels and the 8:7 pixel shape of a TV. Another button
shows or hides the overscan lines a TV would crop.

The keyboard drives both controllers, so it also plays Luigi in a two player
game. With two gamepads connected, the second one is controller 2. A real
D-pad can't press left and right together, so when both keys are down only the
last one pressed counts.

As on the original:

- **Select** chooses between 1 and 2 player games on the title screen.
- **Continue:** after a game over, hold A and press Start on the title
  screen. You restart at the first level of the world where the game ended.
- **Second quest:** after beating 8-4, press B to go back to the title
  screen. Hard mode is now on, and B on the title screen picks the starting
  world.

One addition: if the window loses focus during play, the game pauses itself
(it presses Start for you).

## What's in the box

| Path | Contents |
| --- | --- |
| `src/game/` | The port of the game program. `frame.js` has the frame handler, modes and screens. `area.js` is the level parser. `engine.js` covers player movement and objects, `enemies.js` the enemies, `collision.js` collision, `gfx.js` sprite drawing, and `sound.js` / `music.js` the sound engine. Routine names follow the disassembly. |
| `src/core/` | The parts that stand in for the console. `machine.js` holds 2 KB of RAM and the 6502 carry flag helpers. `ppu.js` is the picture processor model: nametables, palettes, the 8 sprites per line limit and the status bar split. `apu-synth.js` is the sound chip (two pulse channels, triangle and noise), running in an AudioWorklet. `input.js` handles input, `audio.js` audio output and `userrom.js` the optional ROM. |
| `src/gfx/` | The artwork, drawn for this project as text pictures and cut into the 8x8 tiles the engine uses, plus the title screen layout. |
| `src/data/romdata.js` | Data tables (levels, enemy lists, physics tables, palettes, text), generated from the disassembly by `tools/extract-data.mjs`. |
| `src/data/romlabels.js` | Where certain tables sit inside the original ROM, generated by `tools/asm-labels.mjs`. These are addresses only. |
| `src/main.js` | Startup, the frame loop, video scaling and the page controls. |
| `tools/serve.mjs` | The small static web server behind `npm start`. |

The game runs at the NES frame rate of 60.0988 Hz with a fixed timestep. On
60 Hz displays it steps one frame per refresh, so scrolling stays smooth.
Scaling is nearest-neighbor at whole-number multiples where the window allows.
Otherwise it pre-scales with nearest-neighbor and then filters lightly, which
keeps pixel edges sharp without making some pixels wider than others.

## Graphics and music: what differs from the original

No graphics or music from the cartridge ship with this project.

- **Graphics** are new pixel art in the original's style. They use the same
  tile layout, sprite sizes, animation frames and palettes, so everything
  lines up with the engine. They are not copies of Nintendo's artwork. The
  title logo is also redrawn.
- **Sound effects** are complete. The original sound effect routines are
  ported and play through an emulated NES sound chip.
- **Music** is not included, so by default you hear sound effects only. The
  engine still tracks the music, because the game waits on it: the death
  jingle, the end-of-level fanfare, the castle tune and the "hurry up" speed
  change all keep their original lengths, so game timing matches.

**Original graphics and music from your own cartridge.** If you own the game,
use **Load ROM file…** in the side panel to pick your ROM (an iNES `.nes`
file of *Super Mario Bros.*, World version). The game then uses its graphics,
its title screen and its music. The music plays through a port of the
original music engine reading the note data in your file.

The file is checked against known table contents. It is stored only in your
browser's local storage, and **Forget ROM** removes it. The checkboxes next to
the button switch the graphics or the music back to this project's versions.

**Your own audio files** are a third option. `assets/music/tracks.js` can map
tracks (overworld, underground, castle, star, death and so on) to audio files
you put in `assets/music/`. They play when the game changes tracks.

## Accuracy notes

The port follows the disassembly closely: same RAM layout, same carry-flag
behavior and same table data. The differences are limited to the console
hardware around the program, plus one change for the redrawn art:

- **Status bar split.** The original finds where the status bar ends with a
  sprite collision test (sprite 0 hit). Here the split is fixed at line 32,
  close to where the original's split falls.
- **Lag frames.** The original never ran out of time within a frame, so there
  are no lag frames to model. Each frame runs in well under a millisecond.
- **Mushroom retainer sprite.** The original draws the top half of the
  mushroom retainer (the Toad character) from the same tiles without
  mirroring. With the redrawn art, the right half is mirrored. This switches
  off when ROM graphics are loaded.
- **Sound mixing.** The sound chip is emulated per audio sample with the NES
  mixing curve and output filters. The game never used the DMC sample
  channel, so only its output level is modeled. That level matters because
  the game raises it during some songs, which slightly lowers the triangle
  and noise channels.

## How it was tested

- **Automated play in Node.** A script loads the engine without a browser and
  steps it frame by frame. A simple bot played World 1-1 from the title
  screen to the castle: stomps, flagpole score, time bonus, castle flag, then
  on to 1-2. It also ran in every one of the 32 levels with no errors and
  beat 1-4 (Bowser, axe, bridge). Scripted checks covered:
  - ? blocks, the mushroom and growing, and breaking bricks
  - entering a pipe and visiting the bonus room
  - death, game over and returning to the title screen
  - the World 8 ending and the switch to the second quest (started by
    setting the world number while a castle was being cleared, not by
    playing through)
- **In Chromium (Playwright).** These checks covered:
  - frame rate (60.15 fps measured)
  - keyboard input
  - pause and the game's pause timing
  - audio start-up
  - window scaling, including a phone-width layout
  - loading, validating, persisting and forgetting a ROM (with a test image
    assembled locally from the disassembly, which is not part of the
    project)
- **Graphics.** Scenes from several worlds were rendered with this project's
  art and with the original tiles side by side, to check sprite direction and
  tile placement.
- **Music engine.** The ported engine reproduces the opening notes and
  rhythm of the overworld theme.
